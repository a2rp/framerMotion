# Installation and project setup

This lesson installs Motion for React in an existing React project and checks that the application can render a motion component. Current examples use the `motion` npm package and the React import path `motion/react`. The current installation guidance requires React 18.2 or newer. Check the requirements for the version selected by your project before upgrading an existing React application.

## Before installing

Confirm that the project already runs without Motion. From the project root, install its declared dependencies and start its normal development server. This separates an existing React or bundler issue from a Motion setup issue.

A typical Vite React project contains:

~~~text
my-app/
  package.json
  package-lock.json
  index.html
  src/
    main.jsx
    App.jsx
~~~

Use the package manager that already owns the lockfile. If the project has `package-lock.json`, use npm. If it has a pnpm or Yarn lockfile, use that package manager rather than adding a second lockfile.

## Install Motion

For an npm project:

~~~bash
npm install motion
~~~

This adds Motion to `package.json` and updates the npm lockfile. For a pnpm or Yarn project, use the corresponding add command instead. Commit the manifest and lockfile together so another environment resolves the same dependency tree.

Do not install the legacy `framer-motion` package in a new example in this course. Existing projects may still depend on it; handle those in the [migration chapter](029-migrating-from-framer-motion-to-motion.md).

## Import the React API

In a React component, import the API from the React entry point:

~~~jsx
import { motion } from "motion/react";

export function Welcome() {
  return (
    <motion.h1
      initial={{ opacity: 0, y: 10 }}
      animate={{ opacity: 1, y: 0 }}
      transition={{ duration: 0.3, ease: "easeOut" }}
    >
      Motion is installed
    </motion.h1>
  );
}
~~~

Use `motion/react` for React components and hooks such as `motion` and `useScroll`. The base package also exposes non-React APIs, which are outside this React setup example. A later chapter explains specialized entry points for React Server Components and smaller feature bundles.

## Add a component to the application

In a Vite React application, the root component is commonly rendered from `src/main.jsx`. Keep the application bootstrapping in that file and put interface content in a component such as `src/App.jsx`.

~~~jsx
import { createRoot } from "react-dom/client";
import App from "./App.jsx";

createRoot(document.getElementById("root")).render(<App />);
~~~

~~~jsx
import { motion } from "motion/react";

export default function App() {
  return (
    <main>
      <h1>Project setup</h1>
      <motion.p
        initial={{ opacity: 0, y: 8 }}
        animate={{ opacity: 1, y: 0 }}
        transition={{ duration: 0.25 }}
      >
        The paragraph animates after React renders it.
      </motion.p>
    </main>
  );
}
~~~

The exact entry filenames can differ between projects. Preserve the structure generated by the project's existing framework.

## Verify the dependency and import

Check the installed dependency tree with:

~~~bash
npm ls motion react
~~~

Then run the normal development command from `package.json`, commonly:

~~~bash
npm run dev
~~~

A successful setup means the app starts, the component renders, and the entrance animation can be observed. This lesson does not claim that a build was run for every learner's local environment. If the import fails, verify that the package installation finished and that the import path is exactly `motion/react`.

## TypeScript projects

Motion for React includes TypeScript declarations. Install `motion` in the TypeScript project and import its React APIs from `motion/react`. Keep the component's props typed as usual. For example, a target object can be inferred inline:

~~~tsx
import { motion } from "motion/react";

type StatusProps = {
  active: boolean;
};

export function Status({ active }: StatusProps) {
  return (
    <motion.span animate={{ opacity: active ? 1 : 0.5 }}>
      {active ? "Active" : "Inactive"}
    </motion.span>
  );
}
~~~

If a type error appears, first check that the installed package and TypeScript version are supported together. Avoid installing a separate old type package unless the official package setup for your chosen version asks for one.

## Framework and environment notes

- **Vite:** Install Motion and import it from a React module. No special Vite configuration is normally needed.
- **Next.js App Router:** Interactive components that use hooks and browser events need a client boundary. The dedicated [Next.js lesson](027-nextjs-server-rendering-and-react-server-components.md) covers the server-compatible entry point and client component choice.
- **Server rendering:** A motion component can render an initial state on the server, but browser interaction and hooks still need the appropriate client environment.
- **Multiple package managers:** Keep one lockfile and use its matching package manager.
- **Dependency versions:** Package releases change. Follow the React and Motion requirements for the version actually installed rather than relying on a copied version number.

## Common setup problems

- **Cannot resolve `motion/react`.** Check the project root, install command, and package manager. Confirm `motion` appears in the dependency tree.
- **Importing from an old package in a new example.** The code in these notes uses `motion/react`. See the migration lesson for existing projects.
- **Running the command from the wrong directory.** Run npm from the directory containing the intended `package.json`.
- **Two lockfiles appear.** Remove neither automatically. Identify the package manager the project uses, then update only the matching lockfile.
- **The component does not render.** Verify the component is imported into the app tree and that the root entry renders the application.
- **React version mismatch.** Check the React version and Motion's current peer requirements before installing or upgrading.
- **Adding framework configuration prematurely.** First prove the basic Vite or framework setup works; add special entry points only when the application architecture needs them.

## Recap and practice

1. Install `motion` using the project's existing package manager.
2. Import `motion` from `motion/react` in a React component.
3. Render a small `motion.p` and use `initial` plus `animate`.
4. Check the dependency tree and start the existing development command.
5. Keep the package manifest and lockfile in sync.
